# Implementation Plan: Convex Database and Cloud Saving

**Branch**: `003-convex-cloud-saving` | **Date**: 2026-02-07 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/003-convex-cloud-saving/spec.md`

## Summary

Install and configure Convex as the database and file storage layer for FINNISH. Wire Clerk authentication to Convex via JWT template so user identity flows from frontend to backend. Define schema for projects and users tables. Implement mutations (saveProject, updateProject, deleteProject) and queries (getProjects, getProject). Use Convex file storage for project thumbnails. Build auto-save with 30-second debounce. Create My Projects dashboard at /projects. Migrate existing localStorage diagrams to cloud storage on first sign-in.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)

## Implementation Steps

### Step 1: Install and Configure Convex
- Install `convex` npm package
- Run `npx convex dev` to initialize project (creates convex/ directory, .env.local updates)
- Add `VITE_CONVEX_URL` to vite-env.d.ts
- Create `convex/auth.config.ts` with Clerk JWT provider

### Step 2: Wire ConvexProviderWithClerk
- Update `src/main.tsx` to wrap App with `ConvexProviderWithClerk`
- Import `ConvexReactClient` from `convex/react` and `ConvexProviderWithClerk` from `convex/react-clerk`
- ClerkProvider wraps ConvexProviderWithClerk wraps App

### Step 3: Define Schema
- Create `convex/schema.ts` with projects and users tables
- Projects: userId, title, diagramData (string — JSON serialized), thumbnailId (file ref), createdAt, updatedAt, version
- Users: clerkId, email, subscriptionTier, aiGenerationsUsed, aiGenerationsLimit, exportCount
- Add indexes: projects by_userId, projects by_userId_updatedAt, users by_clerkId

### Step 4: Implement Backend Functions
- `convex/users.ts`: getOrCreateUser (lazy creation from Clerk identity), getUser, updateUser
- `convex/projects.ts`: saveProject, updateProject, deleteProject, getProject, getProjects (paginated)
- `convex/storage.ts`: generateUploadUrl for thumbnail uploads
- All mutations validate auth via ctx.auth.getUserIdentity()

### Step 5: Build Frontend Hooks
- `useCurrentUser()`: Calls getOrCreateUser on mount, syncs Clerk identity to Convex user record
- `useProject(projectId)`: Single project query + save/update mutations
- `useProjects()`: Paginated list of user's projects
- `useAutoSave(projectId, canvasState)`: Debounced 30-second auto-save with status indicator

### Step 6: Build My Projects Page
- Create ProjectsPage at /projects (protected route)
- Grid of ProjectCard components showing thumbnail, title, last-modified
- Empty state for new users
- Delete with confirmation dialog
- Click to navigate to /editor/:id

### Step 7: Update Editor for Cloud Save/Load
- Update EditorMode to load from Convex when URL has project ID
- Add Save button with status indicator (saving/saved/error)
- Wire auto-save hook
- Generate thumbnail on save (canvas.toDataURL scaled to 200x150)

### Step 8: localStorage Migration
- Create useMigration hook: detect localStorage diagrams, offer migration prompt
- MigrationPrompt component with accept/decline
- On accept: iterate localStorage keys, save each as Convex project, clean up localStorage
- Store "migration_offered" flag to prevent re-prompting

### Step 9: Build Verification and Polish
- Full TypeScript build verification
- Manual end-to-end testing
- Save status indicator styling
- Error handling and retry logic
